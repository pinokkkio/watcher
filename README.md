# moex-watcher

Мониторинг Московской биржи: уведомления о **сильных** и **аномальных** движениях акций, облигаций
и фьючерсов, плюс рейтинг **самых волатильных** инструментов.

Данные берутся из публичного API биржи [MOEX ISS](https://iss.moex.com/iss/reference/). Без подписки
котировки идут с задержкой около 15 минут. С подпиской на данные можно указать логин MOEX Passport
в `[iss]`, тогда задержки не будет.

## Что отслеживается

**Сейчас включено** (по умолчанию): сообщение о старте и сигналы о **текущих движениях за
последние 15 минут**.

| Сигнал | В сообщении | Когда срабатывает |
|---|---|---|
| `FAST_MOVE` | `+2.3% за 6 мин` (с σ в скобках, если это ещё и аномалия) | цена ушла от минимума (рост) или максимума (падение) за последние 15 минут на ≥2% (акции), ≥1% (облигации), ≥1.5% (фьючерсы) |
| `ANOMALY_FAST` | `+0.8% за 3 мин (5.1σ)` | то же движение необычно для самой бумаги: ≥4σ её дневной волатильности, приведённой к 15 минутам. Ловит рывки «тихих» бумаг (ОФЗ, голубые фишки), которые не дотягивают до порога в %. |

Движение меряется от экстремума внутри окна, поэтому разворот (упали на 1.5% и отросли на 2%)
тоже ловится. Медленный дрейф (+3% за час) — нет.

Антиспам: после сигнала по бумаге следующий в ту же сторону — не раньше чем через 15 минут,
кроме случая, когда движение удвоилось. Разворот в обратную сторону сообщается сразу.
Неликвидные бумаги отсекаются по обороту (`min_value_today`, `min_avg_value`).

**Выключено, включается позже** (`WATCH_SIGNALS` или `signals` в конфиге):

| Сигнал | Смысл |
|---|---|
| `STRONG_DAY` | изменение к закрытию прошлого дня пересекло уровень (акции 3/5/7/10/15%, облигации 1/2/3/5/10%, фьючерсы 2/4/6/10%) |
| `ANOMALY_DAY` | дневное изменение ≥3σ собственной волатильности бумаги |
| `VOLUME_SPIKE` | оборот за день в 3+ раза выше нормы для этого времени |
| сводка | «самые волатильные сегодня» раз в `DIGEST_INTERVAL_MIN` минут |

## Запуск в Docker

```bash
cp .env.example .env
```

```bash
cp config.example.toml config.toml
```

В `.env` укажите `TELEGRAM_TOKEN`, `TELEGRAM_CHANNEL` и параметры прокси, затем проверьте отправку:

```bash
docker compose run --rm watcher watch --test-notify
```

Запуск в фоне и просмотр логов:

```bash
docker compose up -d --build
```

```bash
docker compose logs -f
```

Самые волатильные инструменты из контейнера:

```bash
docker compose run --rm watcher -m shares volatile --mode z
```

История и журнал алертов хранятся в volume `watcher-data`. Журнал можно посмотреть так:
`docker compose exec watcher tail -f /app/data/alerts.jsonl`. Контейнер работает от непривилегированного
пользователя, часовой пояс — Europe/Moscow.

## Telegram-канал

Уведомления публикуются в канал:

1. Создайте бота у @BotFather и получите токен.
2. Создайте канал (публичный или приватный).
3. Добавьте бота в администраторы канала с правом «Публикация сообщений».
4. Укажите канал в `TELEGRAM_CHANNEL`. Для публичного канала подходит `@имя` или ссылка `t.me/имя`.
   Для приватного нужен числовой id `-100…`: перешлите любой пост канала боту @userinfobot или
   @getidsbot. Ссылка-приглашение не подойдёт.
5. Проверьте: `docker compose run --rm watcher watch --test-notify`.

При запуске `watch` бот публикует в канал сообщение о старте: версию, время, список рынков,
активные сигналы с порогами и интервал опроса. Если публикация не удалась, в логе будет причина с подсказкой: бот не добавлен в
канал, нет прав на публикацию, канал не найден.
Старое имя переменной `TELEGRAM_CHAT_ID` тоже работает.

## В канал ничего не приходит

При старте `watch` бот проверяет через Bot API токен, канал и свои права в нём и пишет итог в лог:

```bash
docker compose logs watcher | grep Telegram
```

| В логе | Что делать |
|---|---|
| `Telegram ВЫКЛЮЧЕН: не задано TELEGRAM_…` | переменная не дошла до контейнера: проверьте `.env`, затем `docker compose up -d --build --force-recreate` |
| нет ни одной строки `Telegram` | работает старый образ — пересоберите с `--build` |
| `бот @… канал «…» … статус бота: administrator` | всё настроено |
| `без права публикации` / `бот не добавлен в канал` | сделайте бота админом канала с правом «Публикация сообщений» |
| `это «private», а не канал` / `ушло в чат типа …` | в `TELEGRAM_CHANNEL` указан личный чат — нужен `@имя` канала или `-100…` |
| `прокси отклонил логин/пароль (407)` | неверные `TELEGRAM_PROXY_USER` / `TELEGRAM_PROXY_PASSWORD` |
| `неверный TELEGRAM_TOKEN (401)` | перевыпустите токен у @BotFather |
| `Telegram: в очереди N …` без `опубликовано` | сообщение ещё копится, уйдёт через `TELEGRAM_BATCH_SEC` |

Каждая успешная публикация логируется строкой `Telegram: опубликовано в «<канал>»`.

## Без спама: одно сообщение вместо многих

Сигналы не отправляются по одному. Они копятся `TELEGRAM_BATCH_SEC` секунд (по умолчанию 60) и
уходят одним сообщением:

```
📊 MOEX · 14:12 · сигналов: 6

⚠️ Аномалии
🟢 VKCO VK 327 — +2.2% за 4 мин (4.6σ)
🔴 GAZP ГАЗПРОМ ао 128 — -1.5% за 2 мин (7.7σ)
🔴 BRZ6 BR-12.26 [фьюч.] 62.3 — -1.1% за 2 мин (4.3σ)
🟢 SBER Сбербанк 302.5 — +0.8% за 3 мин (5.1σ)
🔴 SU26238RMFS4 ОФЗ 26238 [ОФЗ] 57.6% — -0.7% за 2 мин (10.3σ)

📈 Сильные движения
🟢 MTLR Мечел ао 104.2 — +4.2% за 4 мин
```

- Одна строка на инструмент. Если по бумаге за окно пришло несколько сигналов, они сливаются в
  одну строку с последней ценой.
- Сначала аномалии, потом сильные движения, внутри — по силе текущего движения. Цвет — направление движения.
- Больше `TELEGRAM_MAX_LINES` строк (по умолчанию 30) или длиннее лимита Telegram — в конце
  «…и ещё N», второе сообщение не отправляется. Полный список есть в `alerts.jsonl`.
- Ежечасная сводка самых волатильных добавляется в то же сообщение, если совпала по времени.
- При остановке контейнера накопленное отправляется сразу.
- В итоге в канал приходит не больше одного сообщения за окно. Сообщение о старте уходит сразу.

## Telegram через прокси

Все запросы к `api.telegram.org` идут через прокси с логином и паролем, запросы к бирже — напрямую.
Переменные окружения перекрывают `config.toml`:

| Переменная | Пример | Описание |
|---|---|---|
| `TELEGRAM_TOKEN` | `123456:ABC…` | токен бота от @BotFather |
| `TELEGRAM_CHANNEL` | `@moex_alerts`, `https://t.me/moex_alerts`, `-1001234567890` | канал для уведомлений |
| `TELEGRAM_PROXY` | `https://proxy.example.com:3128` | `https://` — TLS-соединение до прокси, `http://` — обычный CONNECT-прокси |
| `TELEGRAM_PROXY_USER` | `user` | логин прокси |
| `TELEGRAM_PROXY_PASSWORD` | `p@ss:w/rd` | пароль; спецсимволы экранируются автоматически |
| `TELEGRAM_PROXY_CA` | `/app/certs/proxy-ca.pem` | CA самоподписанного https-прокси, если нужно |
| `TELEGRAM_BATCH_SEC` | `60` | окно склейки сигналов в одно сообщение, секунд (0 — раз в цикл опроса) |
| `TELEGRAM_MAX_LINES` | `30` | максимум инструментов в одном сообщении |

Соединение с Telegram всегда идёт по HTTPS через туннель: сам прокси трафик не видит.
Сертификат https-прокси проверяется, и пока ему нет доверия, логин и пароль прокси не отправляются.
Пароль в логах маскируется. Переменные `HTTP(S)_PROXY` окружения на Telegram не влияют.
Если отправить не удалось, есть повторы с паузой, а при 429 учитывается `retry_after`.
Ошибка авторизации на прокси (407) пишется в лог отдельно.

Прочие переменные: `WATCH_MARKETS=shares,futures`, `ISS_LOGIN`/`ISS_PASSWORD`, `WEBHOOK_URL`,
`MOEX_WATCHER_CONFIG` (путь к конфигу).

```bash
pip install -e .
```

## Использование

Непрерывный мониторинг: в консоль, в `data/alerts.jsonl` и в Telegram, если он настроен.

```bash
moex-watcher -c config.toml watch
```

Только акции и фьючерсы:

```bash
moex-watcher -m shares,futures watch
```

Самые волатильные сегодня по дневному диапазону high-low:

```bash
moex-watcher -m shares volatile --top 20
```

Самые необычные сегодня, по изменению в сигмах:

```bash
moex-watcher -m shares,futures volatile --mode z
```

Историческая волатильность (годовая, %) за 20 торговых дней:

```bash
moex-watcher -m shares,corp_bonds volatile --mode hist --days 20
```

Проверка канала уведомлений:

```bash
moex-watcher -c config.toml watch --test-notify
```

Рынки: `shares` (TQBR), `etf` (TQTF), `ofz` (TQOB), `corp_bonds` (TQCB), `futures` (FORTS, RFUD).
Свои режимы торгов добавляются в конфиге через `[markets.<имя>]`.

Сводку «самые волатильные сегодня» в канал можно включить через `DIGEST_INTERVAL_MIN`.

## Настройка

```bash
cp config.example.toml config.toml
```

Все пороги задаются отдельно для `shares`, `bonds` и `futures`, см. комментарии в
`config.example.toml`. Настройка Telegram-канала описана выше.

Дневная история кэшируется в `data/history.sqlite`. Первый запуск загружает около 60 торговых
дней по каждому режиму, это несколько сотен запросов к ISS. Дальше подгружается только новый день.

## Устройство

```
moex_watcher/
  iss.py         клиент ISS: снимки рынка (securities+marketdata), дневная история с пагинацией
  history.py     SQLite-кэш дневных итогов; σ, средний оборот, ATR по инструменту
  detectors.py   детекторы сильных/аномальных движений, состояние уровней и антиспам
  volatility.py  рейтинги волатильности (исторический и внутридневной)
  notifiers.py   консоль, Telegram, webhook, JSONL
  engine.py      цикл опроса
  cli.py         команды watch / volatile
```

Опорная цена для дневного изменения: у акций и облигаций — официальная цена закрытия прошлого дня
(`PREVLEGALCLOSEPRICE`, запасные варианты `PREVPRICE` и `PREVWAPRICE`), у фьючерсов — расчётная
цена прошлого клиринга (`PREVSETTLEPRICE`). Цены облигаций считаются в % от номинала.
